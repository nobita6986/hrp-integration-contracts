## Verification

The `manifest.sha256` was generated by running
`reconciliation/crm/CONTRACT-03C/consumer-adoption/_tools/scripts/generate-evidence-manifest.mjs`
against the CRM copy of the bundle. The SHA-256 lines in this mirror
match the CRM bytes 13/13 (the manifest itself is also part of the
manifest, which is a tautology — see the verify command for the exact
post-check).

To re-verify after a CRM-side edit:

```
cd <path-to-crm-worktree>/reconciliation/crm/CONTRACT-03C/consumer-adoption/_tools/scripts
node generate-evidence-manifest.mjs <path-to-crm-worktree>/reconciliation/crm/CONTRACT-03C/consumer-adoption/r1
diff <crm>/reconciliation/crm/CONTRACT-03C/consumer-adoption/r1/manifest.sha256 \
     <neutral>/reconciliation/crm/CONTRACT-03C/consumer-adoption/r1/manifest.sha256
```

The two manifests must be byte-identical (and the CRM manifest must
self-verify 13/13).
